# 前端优化提案：运行就绪度与模拟边界

## 目标

在现有「环境体检」抽屉中加一块只读的运行就绪度面板，让用户一眼分清：当前选用什么后端、哪些模块仍是模拟流程、哪些配置只是已选择但尚未验证真实连接。不要把“接口可调用”或“bridge 已配置”显示成“真实任务已就绪”。

## 当前依据

- `GET /api/health` 只返回 Node 运行时、`mock-workbench`、用户档案占位检查和版块优先级。
- `GET /api/decider` 返回决策后端配置；AnyJev 的服务状态没有在此端点中确认。
- `GET /api/course/meta` 返回默认 `mock`/`bridge`、bridge endpoint 和平台列表；该信息不能证明目标平台已登录或会话可运行。
- 作业与竞赛的当前执行器是 mock；独立核验会把模拟产物判为 `INCONCLUSIVE`。
- 现有 `/api/models` 仅返回环境变量 key 是否配置；绝不在面板展示 key 值。

## 实施范围

- 更新环境体检抽屉，展示：
  1. 总体运行模式及档案检查结果。
  2. 决策后端：`mock`、`llm` 或 `anyjev`；若为 `anyjev`，明确显示“后端已选择，服务连通性未验证”。
  3. 刷课：显示默认 `mock`/`bridge`，以及 bridge 地址；mock 标注“进度仅供演示”，bridge 标注“已配置不等于平台已验证”。
  4. 作业、毕设/竞赛：明确标注当前为模拟执行，列出接入真实 Jupyter、检索/编译 bridge 的下一步提示。
  5. 模型配置：只显示所需 key 已配置/未配置，不读取或渲染 secret 值。
- 优先复用现有只读 API。若作业/竞赛的 backend 状态没有 API 字段，只添加安全的静态 metadata 字段；不新增连接探测、运行任务或持久化。
- 部分 API 失败时，其它状态仍显示；失败项标注“暂不可读取”，提供重试入口。
- 保持现有视觉系统和抽屉行为，键盘焦点、窄屏布局和 `aria-live` 状态提示可用。

## 不在本次范围

- 不配置或启动 AnyJev、模型、OCS、Jupyter、检索服务。
- 不读取、展示或发送 API key、token、课程账号、个人档案内容。
- 不声称完成了真实平台登录、课程进度、作业执行、论文检索或编译验证。
- 不自动切换后端，不改变用户的安全确认门禁。

## 验收标准

1. 环境体检中能分别查看总运行模式、决策、刷课、作业、竞赛和模型 key 配置状态。
2. 所有 mock 流程有明确“模拟”标识；任何未验证的服务连接都不会标成“已就绪”。
3. 面板不暴露 secret，只报告配置是否存在。
4. 一个只读 API 失败不会隐藏其它成功返回的状态；错误可重试。
5. 窄屏可读、键盘可操作、焦点可见；不引入依赖或破坏其它抽屉。
6. 不运行测试或浏览器验证；交付汇报改动文件、实际呈现内容和未验证项。

# 前端优化提案：窄屏导航与工作区布局

## 结论

优先修复手机和窄窗口下的整体布局。当前侧栏固定为 256px，而 720px 以下的响应式规则只覆盖课程表局部表单和抽屉；主工作区、全局导航及聊天模型控件仍按桌面布局排列。以 390px 宽屏为例，固定侧栏后主工作区只剩约 134px，聊天和工作台无法正常使用。

本次只做响应式适配，不重做现有深色视觉系统、不新增业务功能或后端接口。

## 依据

- `public/style.css`：`.sidebar` 固定 `width` 和 `flex-basis` 为 `256px`；目前没有针对 `.app` / `.sidebar` 的窄屏布局规则。
- `public/style.css`：现有 `max-width: 720px` 规则只处理课表表单、课表滚动区和右侧抽屉。
- `public/index.html` 与 `public/app.js`：主导航、会话历史和次要工具都放在侧栏中；窄屏不能简单隐藏侧栏，否则会丢失这些入口。
- `public/style.css`：聊天顶栏同时放模型选择、模型 ID、自定义 API 地址和模式状态，小屏没有换行/收纳策略。

## 布局方案

- **桌面（宽度大于 760px）**：保持现有左侧栏 + 主工作区 + 抽屉结构和尺寸，不重排桌面界面。
- **手机/窄窗口（宽度不大于 760px）**：侧栏改为可打开的覆盖式导航抽屉，主工作区占满宽度；在工作区顶部显示一条轻量工具栏，包含“菜单”按钮和当前版块名称。抽屉里继续保留版块导航、会话列表与底部工具入口。
- 点击版块后收起抽屉；点击遮罩或按 Escape 也可收起。菜单按钮需要可见的焦点态与 `aria-expanded` / `aria-controls`，抽屉打开时不应让遮罩后内容误操作。
- **聊天顶栏**：小屏允许控件换行或占满一行；模型 ID 与自定义 API 地址不得挤出屏幕，模式状态仍可见。不要隐藏模型设置。
- **课程表**：沿用现有横向滚动容器，保证周视图可横向查看；其他表单继续单列布局。
- **工作台**：沿用现有窄屏单列卡片；输入和按钮可换行且触控目标不互相覆盖。

不改 API、服务端、存储、课程表数据格式或其他现有功能；不添加依赖。先查看并保留当前工作区已有改动，不覆盖或回退无关改动。

## 验收标准

1. 在 1440px 和 1024px 宽度下，桌面侧栏、主区和抽屉行为与当前一致。
2. 在 760px、390px 和 320px 宽度下，主工作区可用；页面没有整页横向溢出。课程表允许自身横向滚动。
3. 窄屏下可通过菜单访问全部版块、会话历史及四个工具入口；选择版块后抽屉关闭。
4. 抽屉可通过菜单按钮、遮罩点击和 Escape 关闭；菜单按钮状态对辅助技术可读，键盘焦点清楚。

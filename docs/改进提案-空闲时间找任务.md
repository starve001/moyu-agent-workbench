# 改进提案：按课表空闲时间找学习时段

## 目标

在课程表页增加一个轻量的「给任务找时间」面板。用户输入事项名称和所需的连续节次数，工作台从当前周已有的空闲窗口中筛出候选时段，方便用户自己决定何时做。

这项改动把已有的课表空闲窗口变成可直接使用的排期建议，不创建日历事件，也不替用户自动安排。

## 现状与可复用能力

- `lib/timetable.js` 的 `view()` 已返回当前周的 `freeSlots`，每项包含日期、星期、起止节次、节次数和起止时间。
- `server.js` 的 `GET /api/timetable` 已把该周视图返回给前端。
- `public/app.js` 已负责周视图导航和空闲窗口展示，适合作为新面板的入口。
- 现有课程表按单一事实源读取本地数据；新增功能可以只在前端筛选现有响应，不需要新依赖或数据迁移。

## 用户流程

1. 打开「课程表」，切换到想查看的一周。
2. 在「给任务找时间」面板输入事项名称，并选择需要的连续空闲节数（默认 2 节，可选 2、3、4 节）。
3. 点击「查找时段」。
4. 页面按日期和开始节次顺序列出最多 5 个满足节数要求的窗口，展示日期、星期、节次、时间范围和连续节数。
5. 用户自行选择是否采用；切换周次后，可对新的一周再次查找。

## 实现范围

- 在课程表现有空闲窗口区域附近增加一个独立面板。
- 直接读取当前已加载的 `TT.data.freeSlots`；过滤 `slot.periods >= minPeriods`，保留原有日期与节次顺序，最多显示 5 项。
- 保留当前页面中的事项名称和节数选择，便于切换周次后继续查找；刷新页面后不要求保留。
- 输入为空、学期未设置、课表为空或没有符合条件的窗口时，显示清楚的提示，不报错、不伪造建议。
- 示例课表生成的候选时段继续显示示例数据提示。
- 预计只需调整 `public/app.js` 和 `public/style.css`；无需新增 API、配置、依赖或持久化字段。

## 验收标准

- 输入事项名称并选择 2、3 或 4 节后，结果只包含当前显示周且连续节数达到要求的空闲窗口。
- 结果展示日期、星期、节次和时间范围；结果超过 5 项时只显示排在最前的 5 项。
- 翻周后重新依据新周的数据筛选；面板输入值仍保留。
- 没有学期、没有课程数据或没有匹配窗口时，显示相应空状态。
- 事项名称只用于当前页面显示；不上传、不写入课表、不写入任务会话，也不生成日历事件。
- 页面明确说明：建议仅避开已录入课程，用户的其他安排仍需自行判断。

## 边界

- 不自动创建任务、日历事件或提醒。
- 不修改课程、学期、空闲窗口计算规则或任何现有会话。
- 不调用模型、不联网、不引入新依赖。
- 不把「没有课程冲突」表述为「用户一定有空」。
